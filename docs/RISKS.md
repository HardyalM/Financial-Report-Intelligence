# RISKS — top 15

**Likelihood** is how likely the risk is to occur *without* the mitigation: Low, Medium, High, Near-certain.
**Impact** is what happens if it reaches the dashboard: Low, Medium, High, Critical. Critical means a confident wrong number shown to an analyst.

| ID | Risk | Likelihood | Impact | Mitigation | Detected by |
|---|---|---|---|---|---|
| R01 | **Wrong unit scale** (£m vs £000 vs $m), so every figure is out by a factor of 1,000 | Medium | **Critical** | Exactly one unit token per statement; income statement and balance sheet must agree; **ambiguity blocks the pipeline** and asks a human; unit tokens in notes never set the pack unit | E6 fixtures with `£000`/`£m`/missing token; E1 pack-level `unit_scale` comparison (a mismatch fails every cell) |
| R02 | **Company-only statements used** instead of the consolidated ones. Every UK listed group's report contains both, with near-identical headings. | High | High | Scope classifier on title text; `scope=company` pages excluded; `entity_scope_ambiguous` routes to review; proposed `basis` field makes it visible | E6 "company page never chosen"; taxonomy `wrong_statement_scope` |
| R03 | **Adjusted or APM figures chosen** over statutory ones (adjusted operating profit, profit before adjusting items) | High | High | Numbers only from located primary statement pages; highlights, financial review and APM pages are never candidates; alias exclusion patterns; columnar income statements use only the Total/Statutory column | Golden where statutory ≠ adjusted; taxonomy `apm_confusion`; QA-20 trap question |
| R04 | **Sign errors**: bracketed negatives, liabilities printed negative in net-assets formats, costs shown positive | Medium | High | Canonical sign convention per item (SCHEMA §4.2); section-aware sign resolution; balance-sheet identity and subtotal checks; `sign_ambiguous` | E6 property test (flip one liability → a check fails); taxonomy `sign` |
| R05 | **Wrong period**: restated comparatives missed, columns misread by position, columnar income statements, 52/53-week years | Medium | High | Period from parsed dates, never position; restatement markers; statutory-column classifier; `period_ambiguous` gives null | Golden comparative column; taxonomy `wrong_period`, `restatement_missed` |
| R06 | **Number-parsing noise**: note references read as values, footnote markers, dashes, "n/a" | Medium | High | Note-column detector; strict number grammar; unparseable cells are **unparsed, never 0** | Unit tests on the parser grammar; taxonomy `note_column_value` |
| R07 | **Layout breakage**: tables spanning pages or spreads, multi-column reading order, scanned pages | Medium | Medium | Continuation rules with page provenance per row; spread splitting; Azure DI reading order; scans flagged `not_digitally_born` with values capped below τ | Synthetic two-page fixture; taxonomy `multi_page_split`, `dropped_comparative` |
| R08 | **Bank or NHS layout treated as a corporate profit and loss**: meaningless current ratio for a bank, "total income" mapped as revenue, taxpayers' equity mis-mapped | Near-certain | High | Document profile from explicit signals (EXTRACTION §1.4); **current-ratio applicability decided by whether the balance sheet is classified, not by a label**, which also covers insurers; ambiguous type withholds ratios until a reviewer decides; separate alias maps and topic query variants; bank KPIs only as verbatim quotes; NHS bridges only where approved (OQ-4, OQ-5) | M8.1 `company_b` gate: 4/4 corporate ratios `applicability: not_applicable`; E7 synthetic liquidity-ordered balance sheet; E1 on bank cells |
| R09 | **A number altered by a generative parser, the vision model or the mapping LLM** (rounding, rescaling, "tidying") | Medium | **Critical** | **Text-layer anchoring** of every candidate; **the text layer, not the engine, decides row, column and period**; vision only corroborates or trips a review, and never breaks a tie; mapping LLM is number-blind **and its suggestions never publish** (ADR-007); no LLM output field is numeric (ADR-005). *The review found that the draft let an LLM row choice publish via a check that the wrong row also passes; closed.* | Anchoring re-check on every published value (taxonomy `unanchored_value` = P0); scripted engine returning a "corrected" number; E6 gate "0 values published via `llm_pointer` or vision alone" |
| R10 | **Commentary hallucination**: fabricated or misattributed quotes, numbers, arithmetic, advice, or instructions injected via PDF text | Medium (before validation) | High | Code-derived pages; quote substring verification; placeholder-only numbers; naked-number, advice and direction validators; evidence wrapped as untrusted data; retry once then drop | RAG §6 T1–T18 (offline, CI), including spelled-out numbers, summary validation and ground-truth sensitivity; live pre- and post-validation rates; E8 must-cover recall; claim-level human rating |
| R11 | **Retrieval misses the right passage**: the same risk repeated in several sections, multi-column order scrambling paragraphs, weak section tree | Medium | Medium | Section tree from outline, contents page and running headers; hybrid retrieval with rerank; section priors; evidence floor gives `insufficient_evidence` rather than thin prose | E3 hit@8; QA-20 narrative questions; taxonomy `retrieval_miss` |
| R12 | **Overfitting to 2–3 goldens and overclaiming**: rules tuned to one layout; "100 % accurate" said in an interview | High | High | Held-out `company_c` kept in `fixtures/holdout/`, untouched until M8.3, then scored once; **synthetic layout suite** (ADR-010) tests layout rules beyond the goldens; results reported as counts and case studies; τ never loosened on dev-golden evidence; limitations page in the UI and README | M8.3 held-out run; E7 in CI; `RESULTS.md` review against EVAL §1 |
| R13 | **Vendor or licence dependency**: outage, price change, API or model deprecation, US data processing for private uploads, PyMuPDF's AGPL licence for commercial use | Medium | Medium | Adapter interface for every vendor; full local fallback (`make dev` with zero keys); content-addressed cache; model ids in config; UK regions where offered; `pypdfium2` swap path for the text layer | CI runs with no keys; a fallback-mode run in `make eval` |
| R14 | **Cost blow-out**: long Claude Code sessions, repeated premium parses, an open upload box on a hosted demo | Medium | Medium | Spend caps on every API account; parse once per document (cache); **v1 is local only**; the v1.1 hosted demo serves precomputed goldens, with uploads behind a password and a daily cap; cost recorded per run | `make eval-live` cost report; daily-cap test when hosting is built (v1.1) |
| R15 | **Scope creep and schedule overrun**: M2 is the long pole; temptation to build UI, chat, peers or charts early | High | High | One sub-milestone per session (**19 sessions plus 2 optional**, re-sized at review); binary gates; stop conditions (PLAN §5); hidden scope removed at review (hosting, extra parser adapters, circuit breaker, charting library); v1.1/v2 lists absorb good ideas | Gate checklist in MILESTONES; CI fails if `web/` exists before the `m3-done` tag |

## Top three to watch

1. **R09 and R01.** These are the only risks with Critical impact. Both are defended structurally (anchoring; blocking on unit ambiguity), not by prompting.
2. **R15.** It is the most likely to stop the project from reaching a demonstrable v1. Protect the M2.1–M2.5 time budget.
3. **R12.** It matters most in interviews. Honest counts beat impressive percentages.
